## 刻意留到下一階段的，請不要當成缺漏

**`props` 的形狀還沒被真的考驗過。** 包裡只有 `TLChevron` 一個元件，而它沒有 props。

我試過為了驗證 schema 而多抽一個有 props 的元件，結論是**做不到「順手抽一個」**：
現有程式碼是在 token 之前寫的，任何元件抽出來都會開出 token 缺口
（`TLCheckCircle` 會開三個、`TLRowValue` 會開兩個），而補那些缺口是設計決策，
在沒有畫面脈絡的情況下決定，比晚一點決定更糟。

所以 `props` 的第一次真實考驗放在**階段 1（設定頁）**——那一階段的目的本來就是
「驗證分子層夠不夠用」。設定頁在設計文件裡自述「無 L3、完全由 L2 組成」，
所以做完會一次給你一整組 L2 分子，那時 schema、props、組成關係才第一次有真東西可看。

同理，這幾項現在都還是空的，是預期的：`molecules/`、`organisms/`、
`composedOf`、`variants`、多狀態的元件。

**已知的 token 缺口**也不用再提，都記在 `CHANGELOG.md` 的「已知缺口」表裡了：

| 缺口 | 規模 |
|---|---|
| `neutral700` 被用 16 處，但沒有語意角色（`textSecondary` 是 neutral600、比它淺） | 跨三個 package |
| `TLFont.display(N)` 用了 16 種字面字級，只有 2 處走 token —— 數字的字級尺度整個不存在 | 全 app |
| Presentation 層 181 處字面樣式 | 見 ratchet 基線 |

第二項是這輪挖到最大的一個，建議在做訓練頁之前一次收斂，那邊數字最多。
